## Event-Driven Programming
- A program is made of *routines* (called **event handlers**) that are called when **events** occur
- Non-determinism: the control flow depends on events
- "programming without a call stack": after each handler execution the stack is empty
- Events vs. Threads is an old debate
### Event Loop architecture
- Main design:
```
class EventLoop {
	
	void run() {
		while(true) {
			event = waitForEvents() //Single and only blocking point
			handler = selectHandler(event)
			execute(handler)
		}
	}
}

class EventQueue{
	void insert(event)
	event extractFirst()
}
```
- Main features:
	- Single thread of control waiting for events and executing handlers
	- an event queue used to keep track of events generated by either the environment or the event handler themselves
	- Event handlers are executed *atomically*: if a certain event occurs while an handler is in execution, the corresponding event handler will be executed only after the current handler has completed its execution -> no concurrency, ordering by design
